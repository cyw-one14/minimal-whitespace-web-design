# 制作与交付

用于设计落地、内容接入、多语言、SEO、验证与上线。仅对项目实际需要的能力执行；本文件不要求每个网站增加 CMS、数据库、多语言或独立后台。

## 技术与复杂度

既有项目沿用其栈、版本、组件和发布流程。新项目按交付环境与需求选择：内容稳定的小站可以静态制作；多记录使用结构化内容和共享模板；运营编辑频繁时才选择合适 CMS；需要账户、交易或实时数据时再设计相应后端。

先收敛内容和模板，再按需要引入编辑能力；无需要求所有网站先静态制作、再重复迁移。不要为了套用本 skill 更换现有框架或引入一组新依赖。

## 双击打开与离线交付（明确要求时）

交付入口 HTML 与完整本地资源，采用相对路径，不依赖远程字体、脚本或媒体。直接 file:// 打开时，模块加载和 fetch 读取本地数据可能受浏览器限制；可用普通脚本、内联数据或适合的预构建单文件方案，不把启动服务器变成用户未预期的必需步骤。

用实际入口离线打开，验证资源、导航、脚本和核心交互。演示邮箱、概念作品和模拟数据明确标注；离线页面不能假装完成了真实提交、邮件接收或服务端认证。若用户要求的能力必须有服务端，说明该能力的运行条件，交付符合要求的启动方式。

## 内容与模板契约

一条业务记录承担身份、路由、分类、显示内容、媒体、排序和发布状态。导航、搜索、列表、详情、SEO 通过共享查询或适配层读取，避免多份人工同步的目录。

把结构、内容、媒体和状态区别清楚，但不强行拆成四个系统。复杂固定页可以保留验证过的语义结构，由绑定层填入可编辑槽位；用 React/其他现有框架重建也可。判断标准是维护收益、结构稳定与最终行为。

内容流检查：

| 改动 | 确认到达公开页面的效果 |
| --- | --- |
| 文案 | 正确语言、正确字段；不被旧翻译或默认值覆盖 |
| 图片/手机图 | 真实媒体 URL、比例、候选图和 alt 更新 |
| 顺序/分组 | 最终 DOM 保持需要的组合容器和阅读顺序 |
| 链接/身份 | 实际路由、搜索、列表与详情一致 |
| 发布/下架 | 公开页、搜索、导航、缓存和 sitemap 按状态更新 |

可缺字段按真实情况处理，不用占位数据伪装已完成。生产必需的规范内容与检查数据放在可部署来源中，不能依赖开发者本机的只读原始资料。

## CMS 与发布（需要时）

追踪“编辑字段 → 持久化 → 查询 → 归一化 → 绑定/组件 → 公开路由”。创建了后台字段并不代表接入完成。

草稿、预览、发布的读取权限在服务端落实。预览使用目标系统的认证和限时授权；前端隐藏或一个可伪造 Cookie 不能保护草稿。公共缓存不能混入草稿，退出后应失去预览能力。

在开发或隔离测试环境验证字段编辑、图片、排序、链接、保存草稿、预览、发布、缓存更新和下架；不要为测试写入生产内容。数据库结构变化遵循目标项目的版本化迁移和恢复策略。

后台、会话、邮箱与密码恢复方案按当前项目的风险、产品需求和适用规则设计。

## 多语言与路由（需要时）

先确定实际语言与默认语言 URL。各可分享页面输出对应本地化内容，语言切换保留对应页面和有意义的查询/锚点。语言偏好不能覆盖用户直接打开的明确语言 URL。

业务文案采用目标项目的唯一来源。引入 CMS/服务端本地化后，移除已经被替代的浏览器覆盖行为，避免新发布的内容又被旧翻译写回。

检查标题、正文、按钮、导航、空态、错误、alt 与 SEO；约定缺译回退，明确尚未确认的翻译。后台字段标签可以本地化，不为界面翻译改业务 slug / API 身份。

用目标语言真实长文检查布局，按语言调整列宽、换行与断点。旧 URL 需要兼容时建立永久重定向并验证真实响应，未知路由返回正确 404。

## SEO 与公开状态

按实际项目生成 title、description、canonical、可用语言的 hreflang、分享图、robots、sitemap 和合适结构化数据。数据来自同一已发布内容源；草稿/预览不进入公开索引。

没有真实价格、库存、评价、合作账号时，不生成 offers、review、aggregateRating 或 sameAs。公开联系信息也来自当前品牌，不能从其他案例复制业务资料。

检查不存在路径的 HTTP 404，而不只查看 404 画面；旧址的永久跳转、正式 canonical 与 sitemap 保持一致。favicon 使用可靠根路径或框架约定，核对实际资源类型；资源更新使用项目已有版本化与缓存机制。

搜索引擎验证、收录、排名是外部事实，不因 metadata 完整就宣称已收录。需要核实时使用真实平台信息，不填虚假验证码。

## 运行与视觉验证

小改动检查目标功能及直接受影响的共享行为；整站或模板改动扩大覆盖。沿用已有测试、类型和构建命令，不新建只匹配文案或选择器的测试来代替行为。

| 维度 | 有意义的检查 |
| --- | --- |
| 主路径 | 进入页面、识别内容、比较/操作、到达真实下一步 |
| 交互 | 链接、菜单、搜索、选择、下载、表单或核心工具流程及错误状态 |
| 内容接入 | 文案/图片/排序/链接编辑实际生效；适用时草稿不公开 |
| 设备与语言 | 宽屏/桌面/平板/窄手机、关键断点前后、最长目标语言 |
| 动态与无障碍 | 键盘焦点、Escape、触摸、减少动态效果；无动画仍可读 |
| 资源与性能 | 无损坏链接/资源、比例稳定、首图优先、下方按需加载 |
| 技术 | 与改动相关的测试、类型检查、生产构建和控制台/网络异常 |
| 公开状态 | 404、跳转、canonical、发布/下架与缓存的真实结果 |

浏览器可用时操作实际页面，不把只读代码当作视觉验收。截图按用户要求、项目约定和实际验证需要选择；既不强制每次出截图，也不把一个截图代表所有设备。不能执行的检查标明具体限制。

HTTP 访问受环境限制时，静态文件可用 file:// 验证布局、资源和本地交互，保留实际执行结果并记录 HTTP 限制。此替代不能证明服务端路由、响应码、缓存、数据库或部署正确；需要这些能力的项目继续采用其可用的运行环境，不为试用扩大网络或系统配置。

交互状态、数据边界、跨路由引用和复杂动画适合行为测试；可逆的小样式调整通常用实际页面检查更有效。已有必要检查通过后，不无理由重复全套测试。

## 上线与可恢复性（请求涉及上线时）

先完成可查看的本地成果与检查，确认已授权的上线范围，按目标项目流程发布。不要从“制作网站”自动推断切换生产域名、购买服务、发邮件或改生产数据库的授权。

有正式应用与数据库时，记录目标版本、配置要求、必要迁移、备份与恢复点。发布后查看服务、公开页面、媒体及关键路径。对轻量托管静态站按其平台流程操作，无需硬套其他项目的基础设施。

分别记录：本地实现、检查通过、代码同步、部署执行、在线验收。Git 更新不会自动证明服务已重启；配置检查不会证明外部服务可用；一次页面验收不会证明长期稳定。

清理旧实现前查运行引用、生成结构、媒体回退和恢复用途。“没有直接 import”不是资源可删除的充分依据。迁移后明确唯一维护入口，历史视觉基准不再双写。

## 可复用任务提示

这些短提示用在对应任务中，可替换当前项目名和目标模块，不必每次同时使用。

**页面微调**：以当前正式实现为准，定位组件、最终 DOM、内容绑定与断点。只改目标区域，验证相关设备、长文本和既有交互。

**动效故障**：记录触发前后的可见状态、Observer 目标、实际布局行、计时器、重排和减少动态效果。找出状态为何提前结束或一直隐藏，再验证失败条件。

**内容接入**：沿编辑字段到公开 URL 检查文案、媒体、排序、链接与发布状态。防止默认数据或旧翻译覆盖新内容。

**交付核对**：分别说明做了什么、检查了什么、部署了什么、在线证据是什么；为当前缺口提供准确范围与继续路径。
