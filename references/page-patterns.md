# 页面组合与用户路径

按网站需要选用模式。以下说明每种页面如何帮助用户；不是要求新项目同时制作所有页面。

## 先画路径

把用户的进入、理解、比较、行动串起来。产品官网常见路径是“首页 → 分类 → 产品 → 联系/购买”，服务网站可以是“问题 → 服务 → 过程/案例 → 预约”，工具界面则是“定位任务 → 输入 → 执行 → 结果/恢复”。

每个页面明确主要任务与下一个有效目的地，避免所有按钮都回首页或使用无效 # 链接。没有真实价格、客户评价、统计数据或合作品牌时，通过真实工作和作品建立证据，不补虚构数字。

## 全站外壳

共享 Header、Footer、搜索和语言组件。页眉帮助进入关键路径，页脚提供进一步导航和必要的法律/联系信息；信息数量跟项目规模走。

- 品牌标返回当前语言首页，使用真实链接。
- 一级导航文字若承担页面跳转，点击应到达页面。下拉触发有可识别控件；悬停只是精细指针设备的快捷方式。
- 桌面下拉需要稳定的指针通道与合理关闭延迟，防止指针从文字移入菜单时回弹。保留 Escape、外部点击关闭与正确展开状态。
- 手机可以直接进入分类，也可以使用显式展开按钮；依层级选择，不复制仅靠 hover 的交互。
- 菜单、搜索、模态框各有层级，不靠无限增加 z-index 消除冲突。
- Footer 内容共享同一来源。联系人、公司事实、社交地址用当前项目已确认资料，使用当前品牌已确认的内容。

## 首页：用内容形成节奏

首屏表达访问者应当理解的一件事，并给出明确动作。真实主视觉、简短主标题、必要说明通常已足够；没有额外层级用途就不重复放品牌和型号小字。

产品展示网站可以采用的编排是“主产品画面 → 品牌主张 → 不同尺度的重点产品 → 使用场景 → 公司证据”。新项目应按自己的决策顺序增删：

| 内容目标 | 版式选择 | 需要具备的依据 |
| --- | --- | --- |
| 快速理解主产品/服务 | 单一主视觉与清晰文字 | 已知定位与实际能力 |
| 展示重点与选择空间 | 一幅主内容配次级内容；非对称组合 | 各项有明确优先级 |
| 解释使用方式 | 场景影像或真实界面与说明 | 真实场景或可运行流程 |
| 建立可信度 | 实景、过程、案例或可核实资质 | 对应来源或用户确认 |
| 引导下一步 | 单一明确行动，必要时补次级路径 | 真实可达入口 |

多项同等重要且素材足够时才考虑首屏轮播；数量、间隔和指示样式由阅读需求决定。轮播数量、时间与指示样式需要适合当前内容。轮播的运行与可访问性见 [素材与动效](motion-and-assets.md)。

## 列表与详情：从同一记录展开

分类、系列、目录、搜索和详情共用内容身份与路由。卡片只显示比较和识别所需的信息；不要用参数墙挤占产品视觉。

同组产品的图像画布与体量一致，网格列数按内容密度切换。导航产品分页按实际卡片宽度和页大小前进，首尾状态与真实位置一致；不要露出上一页的一角。目录较小时简单本地搜索可足够，内容规模或需求变化后再选更复杂方案。

详情可从下面选用：

1. 主体、名称、用途与主要动作。
2. 变体选择，联动主图、名称、alt 与选中状态。
3. 对决定有用的特性或过程说明。
4. 参数、规格、文档或交付信息。
5. 支持与进一步行动。

缺少某款参数或文档时，按真实情况省略或显示明确缺口，不从别款复制。统一模板允许内容有差异，不要求每条记录伪造完整字段。

组合结构属于布局契约。例如一个主卡加两个并排次卡应保留次卡的共同容器；CMS 排序后仍生成同样语义的组。调整 CSS 前先查看最终 DOM 是否还存在该容器。

## 品牌与关于页面

先组织“我们是谁 → 如何做到 → 有什么证据 → 服务范围/历程 → 信念”等适用主题。没有对应资料时不硬凑六章。

沉浸章节只适合有明确故事、素材和可控内容长度的展示页。通常先采用普通文档流与粘性目录；用户要求沉浸式体验时再设计状态与滚动模型。

采用章节舞台时：

- 文档真实高度承载章节，原生滚动条与当前章节一致；拖动滚动条、点击目录、键盘和触摸都能进入正确内容。
- 高于视口的内容先允许浏览到边界，再进入下一章。手机、缩放与长语言可退回自然流，不强行把内容压成一屏。
- 非当前章节不可点击、不可聚焦且不透出；目录状态与画面来自同一状态。
- 固定侧栏有共享内容边界。最后章节可以自然进入页脚，同步逻辑不能把用户拉回舞台。
- 降低动态效果时内容完整可读。滚动实现的详细条件见 [素材与动效](motion-and-assets.md)。

证书展示保持比例、清晰度和原色，有必要时提供放大查看或静态清单；查看方式应适合当前访客的需求。市场地图只显示有依据的区域与数字，底图默认可见，点亮层独立。大型品牌线条字是可选装饰。

## 联系、转化与支持

组织“可以合作什么 → 我应找谁/如何行动 → 需要知道什么”。负责人、电话、邮箱、预约或表单根据实际业务选择。

公开联系方式使用实际 tel / mailto / 目的链接。合作类型可定位到对应负责人，定位要避开固定导航。无需表单时，直接联系本身就是完整路径；需要表单时，制作提交、校验、成功/失败状态与真实处理流程，不能只做界面。

FAQ、使用指南和文档入口应易查找。隐私/条款等长文用清晰阅读栏和目录，桌面粘性目录、手机原生折叠是可选组合，不把正文包装成很多小卡片。

## 软件、门户与工具的适配

沿用内容边界、层级、真实证据、共享状态与可靠交付的方法；主操作区域按用户频率和信息密度组织。

- 高重复任务突出输入、主操作和结果，不用首屏轮播推开任务。
- 数据对比用适合的表格或图表；品牌留白保留在分区节奏上，不牺牲查看效率。
- 空、加载、错误、无结果、权限等状态属于真实页面；提供符合产品能力的继续路径。
- 表单、列表和编辑器保持键盘、触摸与可恢复状态。动效提示变化，不拖延提交或结果。

页面模式服从任务；不要给后台硬加制造实力、资质证书或公司文化章节。
